Check the requested behavior and final workspace state, then call `finish_task`. Its summary is the final reply the user reads: for a question, conversation, analysis or review, write the answer itself in the user's language, never a note that no change was needed; for code work, write a concise factual Markdown summary. Explanations may require no edits. For code changes, choose and run relevant checks before finishing. Finish reuses fresh checks or refreshes checks already requested; missing validation is reported as unverified. A build does not establish every requested behavior: choose additional tests when the change needs them. When the work changed something visible, attach the most useful screenshots you took in this run (before/after, each state that was asked for, light and dark when relevant) with a one-line caption saying what each one shows. Do not attach screenshots that show nothing new. When a visual change is hard to reach in the full app (an error, empty or loading state, dark mode, a mobile width), load the `component-preview` skill and open the component on its own with `open_component_preview`.

Summarize checks from run_task reporting or read_code @checks: preserve unknown counts, distinguish pending from skipped, and separate observed results from admitted verification and user acceptance.
