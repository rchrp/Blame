# F47: constructed multi-package confirmation of F45

All 18 assignments completed. Each arm achieved **6/6 official, selected, independently functional and strictly audited successes**. No empty Vitest selection occurred, so this campaign demonstrates **no model benefit from the F45 recovery mechanism**. Compared with pre-F45 Light, the candidate consumed more tokens and SDK cost. Its observed advantage over integrated Cline is descriptive evidence on this small constructed panel, not proof of a general or F45-caused improvement.

Three requests were selected before outcomes: request correlation propagation, CSV options/encoding/API forwarding, and token-expiration/error contracts. Each spans packages and an API application, requires a new test file, and preserves existing tests/configuration. Two dependent repetitions use rotated reference/candidate/Cline order. Wrong selectors and recovery are never forced; the known F44 failure remains diagnostic. Pristine inputs pass original regressions but fail the new behavioral contracts; three positive controls pass all checks; three semantic mutations remain green on old tests but fail the hidden oracle. Oracles and control solutions stay outside agent workspaces.

The measured Light snapshots differ only in four F45 production modules: `check-observation`, `light-task-runner`, `light-finish-service` and `light-validation-report` (plus their declaration artifacts). Reference is pre-F45; candidate is the retained F45 correction. All other executable bytes and initial Light prompt/tool contracts match. Later navigation, test-type evidence and Z3 work are excluded. F45 classifies an unavailable selection as a command failure, reports its cwd, retains the exact required obligation as missing and avoids repeating that same current unavailable selection at finish. Genuine code failures remain blocking.

Model/provider: `openai-codex / gpt-5.6-luna / high`, `https://api.blame.so/api/v1`; prompt date fixed to 2026-10-18. Each assignment has a fresh checkout, copied pinned dependencies, an empty offline npm cache and npm 11.6.4 preserved through login-shell execution. Budgets: USD 0.50 SDK soft limit +0.25 uncertainty reserve, 600s +25s watchdog, 40 iterations, 8,192 output tokens and 500,000 serialized bytes per request; panel stop USD 20. Frozen hashes and exact settings are in `protocol.json` and `execution-bindings.json`.

That parser limitation is not scored as a fabricated task failure.

On six strict pairs, candidate/reference is **+8.3% tokens, +1.5% SDK cost, −29.8% duration**: the registered efficiency gate fails. Token differences by task are +35.0% correlation, −3.6% CSV and −14.2% authentication; leave-one-pair-out ranges from −1.8% to +15.1%, and leave-one-task-out from −9.4% to +19.3%. Every assignment succeeded, so all-assigned totals equal paired-success totals here. No trial, intermediate failure or slow response is excluded.

Duration is confounded by large gaps within streamed model-response iterations: about 181.7s and 121.4s in first-repeat Cline CSV, 180.9s in Cline authentication, and 181.4s in reference authentication. These observations do not identify provider/network/SDK/harness causation. No concurrent benchmark, compiler, build or test workload was scheduled during workers; the host is nonexclusive and unknown contention remains possible. The duration differences cannot establish a recovery speedup when the mechanism was unused.

The unblinded manual source/delivery review binds 72 original artifact hashes. An earlier optional delivered typecheck was not repeated after one literal-only new-test edit; the three required final checks were repeated and the independent grader compiled the final tests. One Cline trial listed filenames in its own trial parent after omitting the workspace segment and repeated that path omission in delivery; no other-trial/control/oracle solution content was retrieved. Signature/body editing friction, new-test expectation failures and corrections remain in the evidence. Finite oracles and this review cannot prove universal correctness or representative issue success.

Decision: retain the independently demonstrated local F45 correction, while recording a **null activation result and no demonstrated model success/efficiency improvement over reference**. The panel is saturated and small; a future confirmation needs new tasks with naturally arising selection ambiguity or observed production failures, chosen before outcomes. Do not manufacture selector failures to turn diagnostics into confirmation.

Reproduction uses the pinned dependency lock, input archives and frozen executable snapshots, with credentials supplied only through the environment. New model campaigns require fresh work/output namespaces and a separately committed registration; never overwrite or rerun these assignments.
