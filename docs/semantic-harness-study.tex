\begin{abstract}
Prioritize audited success and truthful evidence before resources at comparable
quality. Current Light combines syntax navigation, configured JS/TS identity
and guarded edits behind five primitives. Historical 21/36 versus integrated
Cline 28/36 and incomplete consumption do not describe current code. F57 adds
ordinary-search declaration routes, observed body-edit headers and failed-check
priority while preserving final-source obligations. F59--F61 execute 54 registered
assignments with two repetitions: isolated known-task repair/header panels and
fresh cross-module TS-Pattern requests. F59 saves tokens without observed direct
repair uptake; F60 retains two functional failures despite passing authored tests,
with no header exposure in those trials. F61 audits reference/current/Cline at
5/6, 6/6, 6/6; the reference failure is a new test's compilation, not production
behavior. That bundle uses 54.2\% fewer tokens and 38.6\% lower SDK estimated
cost than Cline, with 27.4\% longer agent time. Token savings survive task/pair
omission; the registered duration/resource gate fails. All 54 original patches
reproduce their bounded endpoint outcomes. These small panels establish neither
causal mediation nor general efficiency. F62 adds bounded validation history,
boundary sensitivity controls and passive HTTP timing. Its eighteen known-task
assignments audit reference/candidate/Cline at 4/6, 5/6, 6/6; no candidate receives
the new invalidation feedback, so no model benefit is established. Lower candidate
tokens coexist with lower overall quality than Cline and 8.9\% longer time.
Cache/invoice limits and unknown F52
consumption remain explicit; Z3 stays optional and is disabled in the new panels.
F65 resolves a formatter-observer blind spot and demonstrates actual SDK clipping
with loopback controls: exact scope metadata survives in 4/4 corrected cases
versus 2/4 raw cases. F66 finds no batch use in four trials and rejects that
prototype. F67 observes failed-compiler-first order in 4/4 corrected runs versus
0/4 reference, at equal bounded correctness but 4.6\% more tokens.
This is transport/repair reliability, not a general efficiency result.
Finite experiments cannot establish exhausted improvement margin.
\end{abstract}

\section{Scope, versions and evidence boundaries}
This compact report separates implemented behavior, historical measurements,
new measurements and proposals. Expanded phase-by-phase notes are preserved
verbatim, with byte/hash inventory, in
\filepath{docs/experiments/light-harness-study-history-2026-10-15}.
Original campaign artifacts remain separate. Neither dependent repeats nor
local replay cases count as independent real-issue confirmations.

F28--F31, F34--F36, F38b, F41--F44, F47 and F50 use \code{openai-codex}/\code{gpt-5.6-luna}/\code{high} and
Cline SDK 0.0.82. Native comparison arms include a pinned research search repair;
these are not unmodified CLI comparisons. Actual schemas, prompt sources, model/effort,
source/checker/environment hashes, ordered assignments and budgets are retained.
Light emits seven tools in these runs: five harness primitives and optional
skills/web support; native emits five. Normalized contracts are not literally
identical dynamic prompts. Checkout labels and review are unblinded; provider
revision/seeds and complete cache/invoice accounting remain unknown.

Four claims remain distinct: tests executed, tests passed, verification admitted
for a source/environment/scope, and satisfaction of user criteria. A process exit
or model summary alone proves neither the latter two nor an exhaustive test run.
Unknown counters are not zero; pending, skipped and runner-specific todo labels
must not be silently interchanged. Raw recorded output need not be model-visible.
